# Repository layout

| Path | Contents |
| --- | --- |
| `app_faces/` | Python client and shared interface catalogs |
| `adapters/kde/` | KDE plugin, metadata, build configuration and runtime helper |
| `adapters/kde/tests/` | Compiled plugin and isolated Dolphin tests |
| `backend/src/` | Worker and moderation interface source |
| `backend/migrations/` | D1 schema migrations |
| `backend/tests/`, `backend/e2e/` | Worker integration and browser flows |
| `tests/test_*.py` | Python unit and component tests |
| `tests/integration/` | Desktop, file lifecycle, coverage and contribution runners |
| `tests/fixtures/` | Generic artwork and application fixtures |
| `tests/mutations.py` | Targeted assertion checks using deliberate defects |
| `scripts/` | Setup, checks, deployment inspection and local catalog maintenance |
| `bin/`, `install.py` | Checkout command and user installation entry point |
| `docs/` | Configuration references, design research and verification records |
| `state/`, `build/`, `dist/`, `backend/build/` | Ignored reports, downloads and generated outputs |

Application-specific cases belong in test fixtures or historical verification
records. Runtime code must not depend on the developer's Downloads folder,
installed application names, test artwork or private reports.

The dashboard bundle is generated by `npm run build`; development, test and deploy
commands run this build automatically. Test runners are shipped in the source
archive; only `app_faces/` is included in the Python wheel.
