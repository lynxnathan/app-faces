# Interface languages

Desktop and moderation interfaces share the JSON catalogs in
[`app_faces/locales`](../app_faces/locales).

| Code | Language | Direction |
| --- | --- | --- |
| en | English | LTR |
| zh | Chinese, simplified script | LTR |
| hi | Hindi | LTR |
| es | Spanish | LTR |
| fr | French | LTR |
| ar | Arabic | RTL |
| bn | Bengali | LTR |
| pt | Portuguese | LTR |
| ru | Russian | LTR |
| ur | Urdu | RTL |

These are the initial ten supported languages, not a claim about the ten largest
Linux user populations. Code, identifiers, tests and documentation use English.

## Selection

Desktop priority is `APP_FACES_LANGUAGE`, then the colon-separated `LANGUAGE`
preferences, then the first defined value of `LC_ALL`, `LC_MESSAGES` or `LANG`.
Region, encoding and modifier suffixes are normalized. Unsupported preferences
fall through to the next preference; an unsupported explicit override falls back
to English. `C` and `POSIX` select English.

```sh
APP_FACES_LANGUAGE=fr app-faces gui /path/to/application
```

The environment override applies to each newly opened interface. GTK follows the
selected text direction. User names, file paths and contribution metadata remain
unchanged.

The web interface uses browser language preferences, with English as the fallback.
There is no language selector or saved language override. Dates follow the selected
locale. Arabic and Urdu set the page direction to RTL; identifiers and URLs remain
LTR and user-written reasons use automatic direction.

## Messages and values

English messages are catalog keys. Both clients use explicit translation calls for
application text. Static web text is translated before login; submitted names and
reasons are inserted with `textContent`, never interpreted as HTML or translated.
Named placeholders preserve values and allow language-specific word order. Count
labels such as `Contributions: {count}` avoid English-only singular/plural rules.

All catalogs ship with the Python wheel and are bundled into the moderation UI.
No translation service is called at runtime. Missing keys fall back to English.
Application IDs, API states, license metadata and diagnostics from external
libraries remain language-independent or in their original language.

## Validation

- Catalog key parity, nonempty messages, duplicate-key detection and matching parameters.
- Python call-site coverage, locale precedence, fallback and literal user-content preservation.
- GTK chooser labels, direction, unchanged application names and sharing disabled by default in all ten languages.
- Firefox flows in all ten languages: browser detection, invalid login, localized errors, review cancellation and correction submission to real local D1.
- Unicode application names and reasons remain unchanged in storage; markup in an application name remains text.
- Mobile overflow checks and local screenshots, including RTL review dialogs.

Run the Python and browser suites through `scripts/check-all.sh`. GTK checks are
explicit: run `APP_FACES_GTK_TEST=1 uv run pytest tests/test_native_ui.py` inside an
isolated graphical session. See [development](../DEVELOPMENT.md) for isolation.

These checks validate integration and structural coverage. The translated wording
has not received independent native-speaker review in every language.
